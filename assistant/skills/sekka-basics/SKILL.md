# Sekka basics

Sekka is NixOS for x86_64 PCs, with Determinate Nix, its own desktop
(**Aizome**), an installer (**Genkan**) and a software and update manager
(**Yukimi**). Almost the whole system is built from configuration in
`/etc/nixos` into the read-only Nix store; a change is either a per-user
setting that applies at once, or a configuration change that is built and
then activated.

## The pieces

| Piece | What it is | Run |
|---|---|---|
| Genkan | Graphical installer. Erases one whole disk (no dual boot); writes `/etc/nixos` | live media only |
| Aizome | Default desktop: compositor, shell (menu bar, Deskbar, palette, lock screen) and apps, in Rust | log in to "Aizome" |
| Tatami | Sekka's keyboard-driven tiling desktop (Hyprland-based) | log in to "Tatami" |
| Other desktops | Plasma, GNOME, Xfce, vanilla Hyprland, chosen at install or later | login screen lists them |
| Yukimi | Software, updates, history, store space, desktops — on every desktop | `aizome-yukimi` |
| Settei | Aizome's Settings | `aizome-settei` |

- Login screen: Aizome's own (greetd + `aizome-greeter`) when Aizome is
  installed; GDM when GNOME is installed (GNOME locks only under GDM);
  else Plasma Login. `calamares.loginScreen` overrides (`auto`, `aizome`,
  `gdm`, `plasma-login`).
- Login shell is bash; with Aizome, terminals open **fish** (Omarchy's
  setup: Starship, vi keys, fzf, zoxide, eza). `calamares.fish.enable`
  turns that off or on (Yukimi → Desktops → Terminal shell).
- Programs built for other distributions run through nix-ld (common C/C++
  runtime, zlib, OpenSSL, curl, systemd libs only). A script asking for
  `/bin/bash` won't start (NixOS has no `/bin/bash`).
- Generations are not backups: going back restores the system, not files.

## The installed configuration: /etc/nixos

| File | Contents | Who edits |
|---|---|---|
| `flake.nix` | Generated by Genkan. `inputs.sekka.url = "github:bitemyapp/sekka/nightly"`; `nixpkgs`, `determinate`, `fh`, `applications`, `ai-apps`, `omp` follow Sekka's. One `nixosConfigurations.<hostname>` with `determinate.nixosModules.default`, `sekka.nixosModules.default`, `./configuration.nix` | `sekka-update`/Yukimi (inputs); rarely by hand |
| `flake.lock` | Exact revisions | `sekka-update`/Yukimi only |
| `configuration.nix` | The machine's choices (below) | the person, carefully |
| `hardware-configuration.nix` | Disks, filesystems, kernel modules | leave alone |
| `yukimi.nix` | Packages/programs Yukimi installed "for everyone"; imported by the main file | Yukimi |

Related: `/etc/nixos-secrets/user-password.hash` (root-only; never read,
print or copy it), `/etc/installer-applications.json` (catalog apps
installed, with versions), `/etc/yukimi/system.json` (Yukimi's view of the
system: its Nixpkgs, unfree policy, configuration location, catalogs and
the choices it may change), `/var/lib/yukimi/configurations/` (the configuration behind each
generation, which Yukimi's History restores).

### What Genkan writes in configuration.nix

```nix
imports = [ ./hardware-configuration.nix ];
calamares.installUser = "alice";
calamares.applications = [ "firefox" … ];   # installer catalog ids
calamares.desktops = [ "aizome" "tatami" ];
calamares.defaultDesktop = "aizome";
calamares.tuning.enable = true;              # CachyOS-inspired tuning
calamares.bootSplash.enable = true;
boot.loader.systemd-boot.enable = true;      # UEFI (GRUB on BIOS)
networking.hostName = "…";
networking.networkmanager.enable = true;
time.timeZone = "…";                         # see the note below
i18n.defaultLocale = "…";
services.xserver.xkb.layout = "…";           # system keyboard (login, console)
services.xserver.xkb.options = "altwin:swap_lalt_lwin";  # only if Alt/Super swapped
console.useXkbConfig = true;
services.printing.enable = true;
services.pipewire = { enable = true; alsa.enable = true; alsa.support32Bit = true; pulse.enable = true; };
users.mutableUsers = true;
users.users.alice = { isNormalUser = true; extraGroups = [ "networkmanager" "wheel" ];
  hashedPasswordFile = "/etc/nixos-secrets/user-password.hash"; };
nixpkgs.config.allowUnfree = true;           # or false
system.stateVersion = "…";
```

Its header comment says the `calamares.*` options come from a `calamares`
input; on current systems they come from the `sekka` input
(`sekka.nixosModules.default`). There is no `calamares` input to look for.

### Sekka's own options (verified in the source)

| Option | Values / default |
|---|---|
| `calamares.desktops` | list of `aizome`, `tatami`, `plasma`, `gnome`, `xfce`, `hyprland` (old systems: `cinnamon`, `mate`, `lxqt`; `omarchy` = `tatami`); default `[ "aizome" ]` |
| `calamares.defaultDesktop` | one of the chosen desktops; default `aizome` |
| `calamares.loginScreen` | `auto` (default), `aizome`, `gdm`, `plasma-login` |
| `calamares.applications` | installer catalog ids; default `[ "firefox" ]` |
| `calamares.tuning.enable`, `calamares.zswap.enable` | tuning; zswap in front of the RAM-sized swap |
| `calamares.bootSplash.enable` | Sekka's Plymouth splash (Esc shows boot messages) |
| `calamares.fish.enable` | terminals in fish; default on with Aizome |
| `calamares.nvidia.enable` | NVIDIA's driver (Turing and newer) |
| `calamares.binaryCache.enable`, `.numtide.enable` | download from cache.sekka.computer / cache.numtide.com; default true |
| `calamares.usbWake.enable` | USB keyboards/mice wake the machine; default true |
| `programs.aizome.mutableTimeZone` | default true: Settings owns the time zone |

**Time zone on Aizome systems:** Aizome's module overrides `time.timeZone`
to `null` (priority 90, above the plain `time.timeZone = "…"` Genkan wrote),
so the line in configuration.nix has no effect. Change the zone in
Settings → General → Date & Time, or `timedatectl set-timezone Area/City`.

## Three kinds of change

1. **Per-user, live, no password**: Aizome's Settings and apps
   (`~/.config/aizome/settings.toml`, `~/.config/aizome/<app>.toml`),
   default apps (`~/.config/mimeapps.list`, `~/.config/xdg-terminals.list`),
   Yukimi's "install just for you" (`nix profile`). Applies at once.
2. **System, live, through a daemon** (no rebuild; a wheel user at the
   computer is not asked for a password for most): time and time zone
   (timedated), the computer's pretty name (hostnamed), networks
   (NetworkManager), passwords and accounts (AccountsService;
   `users.mutableUsers = true`), printers (CUPS), Bluetooth (BlueZ).
3. **Declarative, needs a rebuild**: packages and programs for everyone,
   services, desktops, login screen, kernel and boot, the system locale
   (`i18n.defaultLocale`; Settings shows it as managed by the system
   configuration), the system keyboard for the login screen and console
   (`services.xserver.xkb.*`), the host name (`networking.hostName`),
   firewall, users' groups. Edit `/etc/nixos`, then apply.

A file under `/etc` that NixOS manages is a symlink into `/etc/static`
(the store). Editing it by hand (after replacing the link) works only until
the next activation; put the durable fix in `/etc/nixos`.

## Applying configuration changes

- **`sekka-update`** (terminal; asks for the administrator password via
  pkexec): updates Sekka to the newest nightly *and* builds the whole
  configuration, including your edits; applies live when safe, else
  prepares it for the next start. Never restarts by itself.
  - `--switch` / `--boot`: insist on applying now / at next start.
  - `--early` (follow `main`, may build locally) / `--nightly` (back).
  - `--choose SETTING=VALUE[,VALUE]`: change a declared system choice, e.g.
    `--choose calamares.desktops=aizome,tatami`,
    `--choose calamares.loginScreen=aizome`,
    `--choose calamares.bootSplash.enable=true`.
  - `--status` (or `--status --json`): pending restart/sign-out, alone.
  - `--print-flake`: show the flake it would write, change nothing (alone).
  - Systems older than the command: `nix run github:bitemyapp/sekka/nightly#update` once.
- **Yukimi → Updates → Update**: the same as `sekka-update`. Early updates
  switch on that page. **Yukimi → Desktops**: desktops, default desktop,
  login screen, boot splash, terminal shell (Apply asks, then builds).
- **`sudo nixos-rebuild switch`**: standard NixOS; builds
  `/etc/nixos/flake.nix` for this host name from the current lock (no
  updates) and activates it. `sudo nixos-rebuild boot` activates at next
  start; `nixos-rebuild dry-build` only evaluates and lists what would be
  built. Prefer `sekka-update` for ordinary use.
- Updates download from caches and never compile, except NVIDIA's driver.
  Yukimi refuses to start an update below 4 GB free; Nix also collects
  unreferenced store paths when a build leaves under 5 GB free.
- After an activation, Aizome posts "Aizome was updated" with **Reload
  Now** (reloads window management and shell, keeps windows). A changed
  compositor core waits for the next login.
- When a restart or sign-out is needed, Yukimi shows one message with a
  button; nothing happens until the person presses it.

Before editing `/etc/nixos`: say what you'll change, keep a copy
(`sudo cp -a /etc/nixos/configuration.nix /etc/nixos/configuration.nix.bak-$(date +%F)`),
make the smallest edit, then build. A failed build changes nothing that is
running (Yukimi/`sekka-update` also put the files they touched back).

## Going back

- **Yukimi → History**: every generation; open one to see what changed;
  going back also restores the configuration files it was built from.
- **Boot menu** at startup (systemd-boot on UEFI, GRUB on BIOS): pick an
  earlier generation when the new one doesn't start. That boot only; make
  it stick from Yukimi's History once it's up.
- `sudo nixos-rebuild switch --rollback`: switch to the previous system
  generation. Does not restore `/etc/nixos`; the next build uses the files
  as they are.
- Storage cleanup removes old generations; once gone they can't be chosen.

## Where things live

| What | Where |
|---|---|
| Aizome settings | `~/.config/aizome/settings.toml` (see aizome-settings) |
| Per-app settings | `~/.config/aizome/<app>.toml` (`hotaru`, `sumi`, `nisshi`, `koe`, `tenki`, …) |
| Session environment overrides | `~/.config/aizome/environment` (`KEY=VALUE` lines, read at login) |
| Aizome state (window places, stall log) | `~/.local/state/aizome/` (`stall.log` there) |
| App data / caches | `~/.local/share/aizome/<app>/`, `~/.cache/aizome/` |
| Notes, screenshots, recordings | `~/Notes`, `~/Pictures/Screenshots`, `~/Videos/Recordings` |
| System-wide Aizome session config | `/etc/xdg/aizome/` (from the store) |
| Logs | the journal (`journalctl`), `/var/log`; Nisshi (Logs) shows both |
| Crash dumps | `coredumpctl` (kept 3 days with tuning on) |
| The running system / generations | `/run/current-system`, `/nix/var/nix/profiles/system-*-link` |

## Before acting

- Read-only inspection is always fine. Ask before any change, say what it
  does and whether it lasts past the next rebuild or login.
- Prefer the least invasive layer: a Settings toggle over a file edit, a
  per-user change over a system change, a live daemon call over a rebuild.
- Never: print or copy secrets (`/etc/nixos-secrets`, Wi-Fi passwords,
  keys), delete the person's files or backups, end their session (no
  `loginctl terminate-*`, no killing `aizome` or `aizome-shell`, no reboot
  without their say-so), or disable security (firewall, sshd hardening,
  polkit) to make something work.
