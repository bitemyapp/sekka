## 1. Idiom fidelity, per target

What fsmentry holds: states, edges (one per ordered pair), the data of each
state, and generated handles (`entry()`, one method per edge, `AsRef`/`AsMut`
for a data state). It has no events, guards, actions, entry/exit hooks or
context (`fsmentry-core-0.4.0/src/lib.rs:563-647` is the entire generated
behaviour). Hierarchy is a machine nested in a state's data (README,
`fsmentry-0.4.0/src/lib.rs:108-153`). So in every target the share that can
be in the crate's mechanism is the **state change** of each row. Effects,
guards and event dispatch are hand-written `match (entry(), event)` code by
design. That isn't a facade: no target keeps a second hand-written state
enum, and the handlers call no `state = …` assignment.

| Target | In the DSL | Hand code beside it | Rows whose state change goes through a generated edge | Grade |
|---|---|---|---|---|
| pointer | `Window` (3) ⊃ `Press` (4) nested in `Inside(Over)` (`src/pointer.rs:42-63`) | track/clear (`:70-110`), all effects, guards (threshold `:132`, owner `:183-189`) | all (Outside→Inside `:225-229`, captures `:179-182`, releases `:164-167`, exits `:233-234`) | idiomatic |
| wrap | `Mode`, 4 unit states, named edges (`src/wrap.rs:12-22`) | cursor, links, saved, `previous` as machine fields (the spec's machine-wide data) | all but RIS, which rebuilds the value (`:214`); 12 of 13 rows | idiomatic |
| polkit | `Agent` ⊃ `Phase` in `Active(Session)` (`src/polkit.rs:30-53`) | back-off and conversation guards, all effects, `Ctx` | all (`:125-174`, `end` `:182-191`, Success `:241-246`) | idiomatic; edge names unused (fix 5) |
| transfer | `Job`, 10 states, group edges for **next** (`src/transfer.rs:46-57`) | frame stack in `Ctx` (`:72-114`), as the reference does; `can_merge` guard (`:180`) | all | under-used: T4/T6 node splits (fix 6) |
| lock | `Screen` ⊃ `Phase` ⊃ `Check`, and `Delay` beside (`src/lock.rs:30-69`) | entry/exit actions (`:134-173`), cross-region guards (`:262`), data updates by direct enum match (`:97-102`) | all | idiomatic; inner graphs not reachable on the live machine (fix 8) |
| install | `Session` ⊃ `Prep`, `Exec` (`src/install.rs:14-48`) | stage effects, room checks (`:193-212`), peek-then-act (`:192-214`, `:233-242`) | all | under-used: unsealed nested machines, route as a bare `bool` (fixes 2, 7) |

Notes:

- lock's `Screen::locked()` (`src/lock.rs:97-102`) matches the enum directly
  for data updates (Typed, Escape, ShakeTick, has_text). This is honest (the
  `AsMut` borrow can't leave a helper) and slightly flatters lock's benchmark,
  since it skips two out-of-line `as_mut` calls per event. Transitions still
  go through the generated edges.
- The nesting is the README's own pattern. The graphs are 4-12 lines each.
  Most of the LoC (1398 against enum's 1165, verified with `sme.py loc`) are
  the handler matches.

## 2. Compile-fail audit (under "Transitions and forging")

fsmentry's transition API is `handle` plus `entry()` handles and their edge
methods, including nested graphs reached the README's way
(`active.as_mut().phase_entry()`). That use of `as_mut` navigates and writes
nothing, so K3/K6 are not forged. Forging means that exist in this slot:

| Means | Generated by | Hideable? |
|---|---|---|
| `AsMut<T>` on every data state's handle (`fsmentry-core-0.4.0/src/lib.rs:633-645`) | crate, public whenever handles are | no (only by making the whole handle API private through `entry(pub(crate) …)`) |
| `#[derive(Clone, Copy)]` on data that carries private state: `Over` (`src/pointer.rs:32`), `Request`/`Session` (`src/polkit.rs:13,23`), `LockscreenData`/`LockedData` (`src/lock.rs:15,23`); snapshot with `*h.as_ref()`, restore with an edge or `*h.as_mut() =` | implementation | yes |
| a nested machine as bare edge data: `Preparing(Prep)`, `Executing(Exec)` (`src/install.rs:41`) take any variant literal | implementation (a seal type hides it) | yes |
| pub fields on transfer's `Ask`/`Replaced`/`Restore` (`src/transfer.rs:18-42`), written through `AsMut` | implementation | yes |
| state enums' pub variants | crate | live state fields are private in all six machines, so only standalone values are affected |

Verified forgeries (each committed the probe it names):

- install: `prepared.executing(Exec::Bootloader)` enters at step 5, and
  `*executing.as_mut() = Exec::Bootloader` from `Files` skips step 4 (I2).
- polkit: `*active.as_ref()` copied, `Dismiss`, `idle.active(saved)`,
  `Dismiss` gives two `Reply` for cookie 7 (K4).
  `*starting.as_mut() = 1` while conversation 2 runs, then `Prompt{conv:1}`
  shows a prompt (K2).
- pointer: a snapshot of `Over` restored after a native drag routes `Up` to
  the old owner (P2's "route to the press owner after a compositor drag",
  the KIT-13 outcome). Without Copy, `mem::swap` of two live machines'
  `Over` through `AsMut` makes a hovering machine send `Up` to node 1 (P1).
- lock: a snapshot of `LockscreenData` in check 1, written back during check
  2, lets `PamDone{1, Accepted}` unlock (L2). `mem::swap` between two
  machines does the same without Copy.
- transfer: `*probing.as_mut() = ItemId(1)` applies item 1's `Probed` (T5);
  `asking.as_mut().can_merge = true` starts a merge (T6);
  `as_mut().aside = AsideId(99)` loses aside 3 (T3).

Re-check of all 36 cases:

- **No case changes class because of forging.** All ten `accept` cases go
  through edges only (W1, K3, K6, T1, T3, T4, T6, L1, I1, I4). No `reject`
  relies on forging. Forging defeats the `runtime` cases P1, K2, T5 and L2,
  so they stay `runtime` (rule 4). K4, P2 and I2 stay `reject` once the
  implementation-chosen means are hidden (fixes 1, 2).
- **Forge cases are missing** for pointer, polkit, transfer, lock and
  install (fix 3). wrap has none: `Mode` has no data states and all fields
  are private. NOTES §4 must say so.
- **W3 is misclassified (`runtime` → `accept`).** `PendingWrap -settle->
  Normal` is the single edge shared by CR/LF/BS/CUP/RI/EL/print (one edge per
  pair, `fsmentry-core-0.4.0/src/lib.rs:476-479`), and nothing stops a handle
  from taking it on HT. That is the slot's own K3 reading ("an edge doesn't
  say why it's taken"), and it holds under either reading in fix 5.
- **Inconsistent framing within the slot.** L7 is probed typestate-style: the
  missing `Held -> Held` edge gives `reject`, although `SleepPending -> Held`
  exists for `Resumed`. K3, K6, T1 and I1 are probed as "the legal edge
  without its event" and come out `accept`. The second framing would also
  make impl-typestate's `prepared.confirm(true)`, `unavailable.choose(..)`,
  `replacement.placed(..)` and `asking.keep_both(..)` `accept`, while
  impl-typestate's own probes target methods that don't exist (`erase`,
  `retry`, `placed` after a failure, `place_at`). fsmentry can match that
  framing with its documented `-name->` edges (fix 5).
- **Standalone variant literals in transition probes**: K1
  (`Phase::Starting(1)`), L3 (`Phase::Locking`), L7 (`Delay::Held`), I2
  (`Exec::Files(false)`), I5 (`Session::Executing(..)`). The missing edge
  decides the class wherever the handle comes from, so the classes stand.
  They should still reach the state on the live machine (fix 8). Shape
  probes (P2-P6, I6, L6) may use literals per the rule.
- `.stderr` files: all fourteen `reject` first errors are the guarantee itself
  (E0599 no such edge or accessor, E0609 no field, E0308 wrong returned data,
  E0061 missing destination data, E0382 consumed handle, E0023 wrong arity).
  None is a typo, an import or a privacy error.

## 3. NOTES.md claims checked

Correct (verified in the crate source or by running code):

- Handles exist only for states with outgoing edges; sink/isolated `Entry`
  variants hold `&mut Data` or nothing (`lib.rs:257-265`).
- `AsRef`/`AsMut` are trait impls borrowing the handle, so a helper can't
  return `&'state mut Data` (`lib.rs:620-645`).
- One edge per ordered pair ("duplicate edge definition", `lib.rs:476-479`).
- The handle's `&mut` field has no `pub` (`lib.rs:271-274`); the README's
  "expose" is wrong.
- A misspelt node silently becomes a state: every name in a transition is
  inserted as a node (`lib.rs:435-463`), and the exhaustive `state()` match
  is what catches it.
- Hierarchy only by nesting (README; no other mechanism in the generator).
- Transitions and accessors aren't `#[inline]` and keep a panic arm
  (`lib.rs:575-604`, `:626-641`). In the release `smoke` binary there are
  144 out-of-line `impl_fsmentry` symbols, called through the GOT: 29 call
  sites in install's `handle`, 27 in pointer's, 20 in polkit's, 35 in
  transfer's, and 2 in wrap's `print` (only `settle`). Each body ends in
  `cmp; jne` to the panic arm, e.g. `phase::Starting::prompted`. `entry()`
  itself is mostly inlined (it is a call-free leaf).
- Not `#[must_use]`; `unsafe(true)` swaps the panic for
  `unreachable_unchecked` (`lib.rs:221-226`).
- Sizes: transfer 48/40, lock 36/28, the others equal (verified with
  `sizes`).

Wrong or overstated:

1. **"Seven of the ten `accept` probes rest on one edge per pair / an edge
   can't demand evidence" (§1, §4).** One edge per pair forces only L1, and
   W3, which is misfiled as `runtime`. None of K3, K6, T1, T4, T6, I1, I4
   needs two parallel edges. An edge *can* demand proof through its
   destination's data type (I4, I1); the limit is that the proof type belongs
   to the node, not the edge. K3, K6, T1 and I1 are `accept` because of how
   they were probed, not because of the crate (§2).
2. **"Handles share no type or trait" (§2 transfer, §6).** Handles of states
   with the same data type share `AsRef<T>`/`AsMut<T>`: transfer's `Probing`,
   `Placing`, `SettingAside` and `Listing` all implement `AsRef<ItemId>`. A
   local trait implemented for the handle types could fold the eight
   two-armed `match ctx.next(out)` blocks (`src/transfer.rs:143,159,168,196,212,245,262,270`).
   True of the transitions only.
3. **"The sibling `Ctx` (forced by the handle borrow)" (§3 sizes).**
   Disjoint field borrows work. `Ctx` is a convenience for `&mut self`
   helpers, and its tail padding is the +8 bytes. Flattening
   `config`/`frames` into `Transfer` gives enum's 40.
4. **Performance numbers disagree.** §3's smoke table has replay-polkit
   16.49 against 10.43 ns (+58%), while §1 cites criterion +9%. Say which
   one stands and that the smoke run is one pass.
5. **§4's rule** ("which edge an event takes … is the handler's → runtime")
   contradicts the `accept`s for T6 and I4, which are pure guards, and leaves
   W3 out. Rewrite §4 under the new rule and list the forging means
   (table in §2).

impl-statum's and impl-smlang's apart from the crate name (diffed).

## 5. Benchmark distortions

None introduced by the implementation: no per-event allocation (the
transfer `Vec` grows only on merges, as in the reference), no `Err`, no
queue, no `dyn`, and `out` passes through generically. Copies of small data
(`*s.as_ref()`) are cheap. The out-of-line transition and accessor calls are
the crate's own codegen. The harness amplifies them: `handle::<Digest>` is
instantiated in `bench`, so calls into `impl-fsmentry` can't be inlined
without LTO. Inside one crate, Cargo's release default (thin-local LTO)
would usually inline them. That holds for every slot's non-`#[inline]`
helpers, but fsmentry has the most of them per event. One `lto = "thin"`
sensitivity row in phase 3 would show how much of fsmentry's gap (polkit,
transfer, lock, install) this accounts for. Coordinator's call; not an
implementer fix.

## 6. Required fixes

1. **must**: Hide the implementation-chosen snapshot means (forging rule 1).
   Remove `Clone, Copy` from `Over` (`src/pointer.rs:32`), `Request` and
   `Session` (`src/polkit.rs:13,23`), `LockscreenData` and `LockedData`
   (`src/lock.rs:15,23`), and from the graph enums that contain them
   (`Window`, `Agent`, `Screen`, `Phase`). Change `state()` to match by
   reference. Without this, verified replays commit K4 (two `Reply` for
   cookie 7), P2 (`Up` to the pre-drag owner) and L2 (check 1 unlocks during
   check 2). The classes stay K4 `reject`, P2 `reject`, L2 `runtime`.
2. **must**: Seal install's nested machines (rule 1). Make `Preparing`'s and
   `Executing`'s data private-field, non-Copy newtypes (`Prep`/`Steps`) whose
   only constructors start at `Checks`/`Erase`, with `prep_entry()` and
   `exec_entry()` accessors like polkit's `Session::phase_entry`
   (`src/polkit.rs:75`). Make the fields of transfer's `Ask`, `Replaced` and
   `Restore` private with read accessors. Without this,
   `prepared.executing(Exec::Bootloader)` (verified) commits I2. I2 stays
   `reject`.
3. **must**: Add one `forge/F-as-mut.rs` per target where `AsMut` stays
   public, each naming the other means in a comment:
   - pointer: `mem::swap` two live machines' `Over` through
     `AsMut<Over>`, then `Up` to node 1 from a machine with no press (P1).
   - polkit: `*starting.as_mut() = 1` after conversation 2 started, then
     `Prompt{conv:1}` is shown (K2).
   - transfer: `*probing.as_mut() = ItemId(1)`, then item 1's `Probed` is
     applied (T5).
   - lock: `mem::swap` of `LockscreenData` between two machines, then a stale
     `PamDone{1, Accepted}` unlocks (L2).

   state that in NOTES §4.

## 7. Overall

The implementation is faithful to the crate. Every state change in all six
targets goes through generated edges, the graphs are the README's idiom
(nesting for hierarchy, one module per graph), nothing is a facade, the
traces and differential runs pass, and the benchmark costs are the crate's
own. The compile-fail table can't be ranked as it stands, though:

- the `accept` column mixes a framing that impl-typestate doesn't use;
- W3 is filed against the slot's own rule;
- implementation-chosen `Copy` and an unsealed nested machine leave forging
  open that could be hidden;
- the new forge cases are missing.

Fixes 1-4 are mechanical. Fixes 5-7 cost about 50 lines and decide whether
fsmentry ranks with typestate on compile-time guarantees (21 `reject`) or
in the middle (14). After them the slot represents fsmentry fairly.
