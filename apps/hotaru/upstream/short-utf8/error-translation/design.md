# Isolated short UTF-8 error translation

This candidate is based on the qualified ASCII source 7e36bc3139a9d6ee0617c30b602aa95f21bd732fba389c73ae176cfe49c74d6d (commit 842d1e2 compiled inputs). Product source is unchanged. The previous short UTF-8 candidate remains rejected and preserved separately; its second validation pass caused an unacceptable truncated-input regression.

For inputs of 32–63 bytes beginning with C2..F4, the existing audited SIMD validator checks a fully initialized 64-byte stack array containing the input followed by NULs. On success, NUL cannot complete an unfinished multibyte scalar, so the original input is valid and ends at a scalar boundary. The one existing unsafe conversion returns a string borrowing that original input. It cannot return a reference into the stack array. Checked copying reads only the original slice, including at a protected page edge.

On failure, let p be valid_up_to and k be the padded error length. The first invalid sequence begins within the original input: appending ASCII to valid complete UTF-8 cannot create an error. Appending NUL also cannot repair a malformed earlier byte or replace an invalid continuation already present, so p is unchanged. If the original slice was truncated, its legal multibyte prefix has 1–3 bytes. The first appended NUL fails as its next continuation; the padded result is Some(k), with p+k equal to original length. Conversely, if p+k equals original length and the original byte at p is a valid multibyte lead C2..F4, all k existing bytes form the accepted prefix and the next byte is the first appended NUL; the original therefore reports None. Invalid standalone leads/continuations consume one original byte even at EOF, and must retain Some(1); the lead check excludes them. Restricted second-byte failures after E0/ED/F0/F4 occur before original EOF whenever that bad byte exists, and retain Some(1). Every other padded error length is preserved.

The dependency's fields remain private. A small private metadata record holds the same offset and optional byte count; no dependency patch or public API change is introduced. Production feed uses the offset; tests additionally require exact error_len equality with std. Error arithmetic is checked and the original byte is accessed through get. The dependency's own Option<u8> error count bounds the conversion.

Validation covers every possible three-byte suffix at both 32 and 63 bytes (33,554,432 cases), every valid Unicode scalar and each of its prefixes at 31/32/63/64 bytes (17,530,368 cases), all final byte values, pair mutations, initialized NULs, alignments, protected-page ends and whole-terminal chunk invariance. The original standalone ASCII path and width/metadata/budget semantics are untouched. Debug and release each pass 146 tests with the same two existing ignored shell fixtures; strict all-target Clippy and two Miri tests pass. Actual unchanged-library gates pass 444 earlier, 3,462 VT and 756 cursor cases checked at three chunk sizes by the integration fixtures.

The completed native trial rejects this candidate for integration: truncated suffixes regress 8.1% and 4.0% by median, although mixed text improves. See summary.json and the archived raw native report. Error translation removes the explicit second validation pass but still pays padding and the SIMD validator's own error diagnosis; correctness does not imply that those costs are harmless. The primary reference baseline remains the current ASCII binary 5755bcf3479b184ff8b05bcf68a22196d386a63258f99754caf380d90c576728.
